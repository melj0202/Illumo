\section{Game domain and rulesets}
\label{sec:game}

\subsection{CellGameModule}
Camera navigation accepts finite world coordinates with absolute value at most
$16(2^{63}-2^{32})$ per axis, reserving space for bounded cache arithmetic.
Commands, sparse metadata, and pending pan/zoom targets validate this range
before mutation. Saves reject invalid camera metadata before replacement.
Invalid cursor samples are ignored; an invalid direct camera preserves the
previous safe view cache. This presentation margin does not limit sparse cell
storage or guarantee cell-level rendering precision at extreme coordinates.
Clipboard operations iterate bounded local offsets even at signed endpoints.
Elementary rules use background beyond representable X coordinates and omit
unrepresentable children; a source row at maximum signed Y rejects advancement
before changing cells or revision.

Primary gameplay module. Owns a \symbolref{CellContext} and an enum
\symbolref{CellState}:
\begin{center}
\texttt{NORMAL} $\mid$ \texttt{EDIT} $\mid$ \texttt{EXIT}
\end{center}

\begin{statusbox}
Mode handling is an \textbf{enum + switch} inside the module, not the older
class-per-state hierarchy (archived under \pathref{archive/old-states/}).
\texttt{E} toggles EDIT/NORMAL and wakes \symbolref{SplashText}.
Save/load, pause/run/step, canvas, ruleset, and camera behavior is exposed as
registered console commands rather than artificial frame states.
Simulation rate: env \texttt{tps} $\times$ \texttt{speedFactor}, with an
accumulator and at most one worker generation in flight. Completed sparse grids
publish only at frame boundaries; overdue whole steps are dropped while the
fractional remainder is retained. Pause/edit, persistence, ruleset changes,
manual stepping, and shutdown drain first. Status separates requested and
achieved published TPS and reports rolling 256-sample generation, cache-refill,
upload-byte, and upload-rectangle p50/p95/max values. Painting and simulation
operate on signed world coordinates. The default topology is infinite and
non-toroidal; positive chunk dimensions select a finite torus.
\end{statusbox}

F1 opens a Release-visible, primitive-composed \symbolref{ConfigurationMenu}.
It configures ruleset, world chunk width/height, TPS, simulation speed, fade
speed, VSync, fullscreen, UI scale, restart-only MSAA, FPS cap, simulation
inspector, and reduced menu motion. FPS presets include uncapped through 360;
custom values accept 0--1000. Zero disables the existing engine software cap;
VSync remains independent. Both main-menu and in-game Apply save preferences
and apply fullscreen immediately. Both dimensions must be positive for a finite
torus; \texttt{0}/\texttt{0} and \texttt{inf}/\texttt{inf} select the infinite
canvas. Applying a topology change drains simulation and starts a fresh
centered world. The overlay uses larger high-contrast labels, readable ruleset
names, split keyboard instructions, and a short explanation for the selected
setting. Pressing Q or activating Exit opens a confirmation overlay; confirming
requests window closure and leaves normal engine shutdown to the App main loop. A short eased reveal, staggered row fade, gliding
selection highlight, and value-change pulse are advanced from frame delta time;
input remains active throughout. Rows scroll with selection, wheel, Page Up/Down,
and Home/End rather than shrinking text to fit the list. Rendering and mouse
conversion share a fitted UI scale. Main-menu F1 opens the same overlay; the
main-menu card adds cyan/violet accents, drifting cell outlines, staggered
labels, and selection glow. Reduced menu motion snaps transitions and stops
decorative motion without changing simulation or cell fading. The in-game
settings button eases its hover highlight and displays the F1 shortcut.

EDIT mode supports Shift+drag marquee selection, Ctrl+C/X/V copy/cut/paste,
Delete fill, R/F buffer rotate/flip, and console commands
\texttt{select}/\texttt{copy}/\texttt{cut}/\texttt{paste}/\texttt{stamp}/
\texttt{rle}/\texttt{plaintext}. Patterns are a side path (D-G1). Optional
\texttt{inspect} HUD reports generation count, hover cell, and census.
Life-like B/S rules share \texttt{LifeLikeRuleSet} masks behind existing mode
strings. Rule 90 and Rule 184 are elementary 1D space-time diagrams (D-G2).
Catalog registration rejects B0 and odd elementary rules: the current sparse
representation requires a stable background in infinite and finite worlds.
JSON catalog loading validates the entire document and all definitions before
publishing replacements. Neighbor arrays accept integers 0--8; elementary rule
numbers and palette channels accept 0--255. Invalid direct life-like neighbor
counts above eight return background before any shift.
Manual stepping counts completed generations and stops at failure. Async failure
preserves the published world, pauses in edit mode and retains one explicit
retry; \texttt{run} schedules it without another time-step charge. Elementary
evolution stages history and destination writes in the retained inactive chunk
map and publishes once. Failed staging preserves live cells, revision and the
previous delta. Empty external sources replace stale spare state; borrowed
source bindings are released on every exit. Staging work scales with history.
Pattern autodetection honors leading \texttt{!} plaintext comments and skips
\texttt{\#} RLE comments. Ambiguous multiline cell-only text uses plaintext
rows; the \texttt{rle} and \texttt{plaintext} commands select their named
parser. Ctrl+V rejects malformed or occupancy-empty clipboard text without
reusing a previous internal pattern or changing the world. Console
\texttt{paste} uses the retained buffer, preserving rotate/flip workflows.
RLE export retains \texttt{o}/\texttt{b} for states 0/1 and uses the project
extension \texttt{p\{N\}} for states 2--255. Parsing accepts braced byte values
and legacy single-digit \texttt{pD} tokens; \texttt{p23o} still means state 2
followed by three live cells. Earlier unbraced multi-digit exports are ambiguous
and require correction to braces. Sparse world saves are unaffected.

The persisted \texttt{render3dTest} flag defaults to \texttt{0}. Setting it to
\texttt{1} replaces CanvasView with a rendering diagnostic scene: fixed axes
and grid plus orbiting, bobbing, spinning solid and wire cubes. Simulation and
UI continue normally; disabling the flag restores the canvas immediately.

\subsection{Domain console commands and persistence}
\symbolref{CellGameModule} registers domain commands through
\symbolref{CommandRegistry}; Services remains free of Game types. Save always
writes version 3 sparse files with magic/version, ruleset, camera, topology,
and sorted 16$\times$16 canonical chunk records. Load validates temporary
state before mutation, accepts versions 3 and 2 plus the prior dense format,
treats older formats as infinite, imports legacy cells around the origin,
restores ruleset/camera metadata, and snaps the bounded view. Native picker variants route through the platform
\symbolref{SaveLoad} API. See D-CLI1 and
\cref{sec:session-2026-08-04}.

\subsection{CellContext}
Constructs two \symbolref{SparseCellGrid} buffers and bounded
\symbolref{CanvasView} from
env vars (\texttt{CanvasX}, \texttt{CanvasY}, \texttt{WorldChunksX},
\texttt{WorldChunksY}) and selects a \symbolref{RuleSet} from the configured
mode name. Mode changes update the ruleset and rebuild the canvas palette.

\subsection{SparseCellGrid (domain) and CanvasView (view --- D-C3)}
\begin{itemize}
  \item Domain: signed 64-bit cell addresses map through floor division into
        non-background 16$\times$16 byte chunks. Negative coordinates and all
        multi-state values are preserved. Infinite mode has no fixed chunk pool
        cap. Finite mode canonicalizes into a centered chunk rectangle and
        wraps both axes.
  \item Simulation: each chunk carries a compact stored-cell occupancy mask and
        a separate neighbor-counting mask plus cached counts for both masks.
        The authoritative and inactive maps maintain aggregate stored-cell,
        counted-cell, and candidate-preferred-chunk totals transactionally
        across edits, local patches, and complete swaps. Settled stepping and
        complete-path selection therefore do not scan every allocated chunk.
        If any source
        chunk has fewer than 48 counted cells, the grid creates exact affected
        targets through a retained generation-stamped
        open-addressed index. Its slots address contiguous scratch records
        containing a 256-bit candidate mask and 256 neighbor counts. It
        derives target participation directly from counting-mask edge and
        corner bits, and initializes a neighbor counter only when its candidate
        bit is first enrolled. Serial preparation remains source-centric for
        locality. For large or explicitly parallel preparation, discovery
        records each target's direct 3-by-3 source references beside its
        neighbor counts. Workers claim retained coarse target ranges and count
        without repeated source-map lookups. Direct dual-grid generations retain
        an object-local topology epoch. When the same source grid returns with
        unchanged chunk presence and counted edge/corner participation, the
        target index and source references are reused exactly. Index-aligned
        destination pointers also avoid output-map lookup when the destination
        topology is unchanged; in-place output preserves their addresses.
        Candidate-index lookup probes existing
        targets before checking whether a new insertion must grow the retained
        table. It evaluates
        only non-background cells and neighbors of counted cells.
        Each target selects candidate or direct halo evaluation independently
        from its counted-neighbor contribution work; counting-dense centers skip
        neighbor-count scratch preparation, and all-dense counted worlds
        bypass scratch construction. This keeps Wireworld conductors separate
        from the heads that actually contribute neighbor counts. Before either
        complete path, a retained changed-chunk frontier records exact state
        and counting-change masks. Every changed chunk enrolls itself, while
        only counting changes on an edge or corner enroll the touching
        neighbor. An empty frontier performs no cell
        evaluation. Up to 16,384 changed addresses are retained for tracking;
        evaluation still follows the frontier/complete work comparison. Sparse local
        sources build candidate masks only for frontier targets and select
        candidates or halos independently. Dense-majority frontiers and
        frontiers with at least 2,048 targets skip candidate scratch and
        evaluate as halo. Exact frontier preparation and
        evaluation work is compared with a complete-path estimate derived from
        cached population totals; cheaper frontiers patch the retained
        prior-generation map directly. At 16,384 or more candidates, retained
        preparation ranges of at most 256 targets and evaluation ranges of
        roughly 2,048 candidate cells use up to four automatic workers and
        independent result slots; smaller sets keep direct serial
        output. Denser worlds use deterministic direct
        halo/core work. Complete targets, their generation-stamped flat index,
        and result slots retain high-water storage. Counted rows are extracted
        directly from chunk masks without materializing an 18$\times$18 byte
        halo; at 32 or more targets a reusable pool evaluates independent cores
        with up to eight workers. Repeated halo neighborhoods may use a bounded
        exact 18$\times$18 state memo. Main and worker shards are lock-free;
        full key comparison proves hits, adaptive sampling enables profitable
        workloads, and ruleset transition changes invalidate entries. Both
        paths write into a retained inactive map
        using recycled node handles before transactional comparison/swap.
        Aggregate inactive statistics reset once before recycling. Sparse
        candidate results construct directly in acquired node storage, while
        dense halo results retain their complete-array bulk copy. Empty
        space is implicit. Infinite mode is non-toroidal. Finite mode enrolls
        canonical wrapped neighbors through the same transition table, so
        horizontal, vertical, and corner seams are exact for binary and
        multi-state rules. The revision changes only when cell contents differ.
  \item Publication: a persistent \symbolref{SimulationRunner} exclusively
        mutates the spare grid while the main thread reads the published grid.
        A completion publishes at a frame boundary. Incremental completions
        carry changed chunk snapshots and update the former display grid before
        it becomes the next worker buffer. Broad completions and journals of at
        least 2,048 presentation chunks carry only a
        replacement marker; the spare advances directly from the immutable
        published grid and updates its own nodes in place. Incremental catch-up uses the grid's retained
        changed addresses and skips states superseded by the incoming delta;
        Only one request may be outstanding. Status separates rolling mirror,
        advance, and capture latency.
  \item View: \symbolref{CanvasView} samples a globally aligned camera cache
        padded by two chunks per side. Motion inside it changes only the MVP;
        aligned origin shifts copy retained texels and resample newly exposed
        strips. One-revision changes map chunks to deduplicated exact or overview bins
        and resample the complete cache when those bins cover a quarter of it;
        marking stops once that threshold is reached. Overview resamples walk
        occupied cells and snap-convert sampled RGB in one pass.
        Near zoom is one texel per cell; far zoom uses integer density LOD with
        80\% refinement hysteresis. Revision gaps, non-aligned jumps, LOD/resize,
        palette changes, torus wrap, and replacement perform a bounded refill.
        Exact-cell LOD fades changing colors; density overviews snap. Finite worlds are
        drawn only inside their centered canonical rectangle; camera space
        outside it stays background-colored while opposite-edge simulation
        neighbors still wrap. Their changes conservatively trigger a bounded
        refill.
  \item GPU: one reusable nearest-filtered RGB display texture and one
        world-space \symbolref{GameVisual} quad that shares its cell bounds
        with the editor cursor. Dirty 16$\times$16-texel tiles merge into at
        most eight rectangles or their enclosing AABB.
  \item Dense \symbolref{CellGrid}/\symbolref{Canvas} remains only for
        compatibility tests and legacy import, not as a second runtime path.
\end{itemize}

\subsection{Scale walls (simulation / memory)}
\begin{statusbox}
Sparse simulation cost follows stored cells, counted cells, and their local
birth candidates, not a fixed world rectangle. Mixed targets independently use
candidates or chunk halos; 32 or more halo targets use up to eight reusable CPU
workers. A cached 256-state by 9-neighbor transition table serves every hot
loop, dense halos use rolling three-row neighbor counts, and profitable
repeated 18$\times$18 states use an exact bounded memo. Presentation uses
a padded camera cache, changed-chunk bins at every LOD, overview snaps, and an
active-texel fade set at exact-cell zoom; fallback refills remain bounded and
far-zoom output stays near one texel
per four screen pixels. GPU
resources do not scale with chunk count.
\end{statusbox}

\subsection{Rulesets}
Active rules are cataloged in \pathref{rulesets.json} and registered via
\texttt{RuleSetRegistry}: Game of Life, Brian's Brain, Day \& Night, Highlife,
Life Without Death, Seeds, Wireworld, Rule 90, and Rule 184. Implementations are
organized by mathematical family: \texttt{LifeLikeRuleSet} for binary Moore B/S
rules, \texttt{Elementary1DRuleSet} for Wolfram 1D space-time rules
(\texttt{NeighborhoodKind::}\allowbreak\texttt{Elementary1D}, D-G2), \texttt{BriansBrainRuleSet} for
3-state decay, and \texttt{WireworldRuleSet} for digital circuit simulation.
Additional rules added to \pathref{rulesets.json} are discovered dynamically at
runtime without C++ recompilation.
\texttt{RuleSetRegistry} constructs built-ins and validates text transactionally.
Game's \texttt{RuleCatalogLoader} selects the first valid catalog beside the
executable, in the working directory, or in its \texttt{IllumoGame} subdirectory.
Invalid or unreadable files fall through without partial publication. The module
factory loads the shared catalog once before menu/direct-game construction.
The engine's configuration path supplies executable location; Rulesets has no
filesystem or native API dependency. Callers use the loader for files and
\texttt{loadFromText} for text (D-GC1).

\begin{lstlisting}
class RuleSet {
  // Pure transition: cell + Moore count of alive (value==0) neighbors.
  virtual unsigned char nextState(unsigned char cell,
                                  unsigned char aliveNeighbors) const;
  virtual void evalCell(const unsigned char& target,
                        unsigned char dest[3]) const; // palette colors
  const TransitionTable& getTransitionTable() const;
};
\end{lstlisting}

\textbf{Generation:}
\begin{enumerate}
  \item Read cached stored/counting totals and the candidate-preferred chunk
        count. If the retained changed frontier is empty, return immediately
        without visiting allocated chunks. Otherwise build its one-chunk
        affected set from exact counting-change edge/corner bits and, for sparse
        local sources, target-local candidate masks.
  \item Compare exact frontier target/source bookkeeping, candidate,
        neighbor-contribution, and evaluation work with a complete-path
        estimate derived from cached totals. Patch the retained map when the
        frontier is no more expensive; otherwise use a complete path. Retain
        at most 16,384 changed addresses for tracking; the work comparison still
        selects evaluation. Edits and ruleset-type changes
        repopulate the frontier.
  \item Use the cached candidate-preferred count to select the complete
        adaptive or all-dense path.
  \item If any source chunk is counting-sparse, create exact affected targets
        directly through the
        retained generation-stamped flat index, reset their contiguous
        masks/counts, mark non-background cells plus neighbors of counted cells,
        then choose candidate bits or a direct halo independently for each
        target from counted-neighbor contribution work. Counting-dense centers
        skip neighbor-count scratch preparation. Dense-majority frontiers and
        frontiers with at least 2,048 targets skip candidate scratch. Large
        sets are divided
        into coarse work-count ranges for the reusable worker pool.
  \item If all source chunks are counting-dense, bypass candidate scratch.
        Build the expanded target set in a retained generation-stamped flat
        index and reuse retained target/result storage. Extract 18-bit counted
        rows directly from the nine chunks' masks, reduce them through three
        rolling horizontal rows, and evaluate serially or through the bounded
        worker pool for 32 or more targets.
  \item For at least 32 halo targets, sample the exact sharded neighborhood
        memo. Activate it only when its observed hit rate offsets key creation;
        cool it down for unique inputs and invalidate it by exact comparison
        of the complete transition table. Instance revisions and rule names
        cannot identify transition semantics across different ruleset objects.
  \item Install non-background results serially into the retained inactive map,
        reusing extracted chunk-node handles before allocating new nodes. Build
        sparse candidates directly in mapped node storage and bulk-copy dense
        halos. Compare
        and swap transactionally only when contents differ.
\end{enumerate}

Before worker dispatch, the active ruleset lazily builds its 2,304-entry
transition table. Candidate, halo, and compatibility dense loops index this
immutable table rather than invoking virtual transitions for every cell.

\begin{decisionbox}[title={Keep rules pure}]
Rulesets stay free of rendering and input. They read/write cell buffers only
and expose \texttt{evalCell} for palette colors. That keeps them testable
(headless \texttt{TestRuleSets}).
\end{decisionbox}
