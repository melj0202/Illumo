\section{Game domain and rulesets}
\label{sec:game}

\subsection{Packaging and execution (D-E13, D-E17)}

IllumoGame ships only as \texttt{IllumoGame.wasm}, played by the generic
\texttt{IllumoRuntime.exe}. The whole product described in this chapter runs in
that store: \symbolref{GuestModuleApplication} composes a guest-local
\symbolref{IllumoContext}, so \symbolref{MainMenuModule},
\symbolref{CellGameModule}, the menus and the workshop run unchanged. Product
dialogs, file transfers, clipboard access and user-catalog writes go through
\symbolref{CSimPlatform}; a native implementation completes synchronously for
the test oracle and the guest implementation completes on a later update.
Saves, settings and user overlays live in the package storage directory. The
package is described by \pathref{IllumoGame/illumo.json} (\texttt{kind}
\texttt{app}, with the module, worker and budgets in its \texttt{app} section;
D-E22) and runs mounted at \texttt{/app} of the host file tree; other
installed packages are visible at \texttt{/packages/<id>}.
Inside the package, \symbolref{SimulationRunner} fans each generation out to
up to eight isolated simulation lanes (D-E17) once serial generations exceed
4\,ms. Each lane is a \texttt{CSimWorkerGuest.wasm} store owning interleaved
bands of eight chunk rows plus a one-row halo; it advances its rows exactly
with the same sparse kernels, and the control store merges the owned changes
into the spare grid as one exact delta and publishes it through the native
publication path. The next generation starts from the halos before the merge,
so lanes compute while the control store merges and renders. Because a lane
generation completes on a later frame, drains retire it instead of waiting:
edits, loads, ruleset changes, saves and exit act on the displayed world.
Small worlds, elementary 1D rules, radii above 16 and lane failures use the
serial kernels inside the update call. The 3D diagnostic records lit meshes
and shadow casters into frame schema version 2; the host re-runs the shared
shadow pass with the guest camera.

\subsection{CellGameModule}

Edit mode includes a bottom \textbf{Cell paint} drawer, initially closed as a
round glass bubble peeking over the footer, with an up chevron and a
paintbrush tipped in the current paint. Clicking the bubble morphs it into the
drawer on two springs (the width leads, the height follows and bounces) and
the drawer's header morphs it back; rounded GuiKit surfaces, UiTheme colors,
and animated row emphasis match the other product menus. Reduced UI motion snaps transitions.
Swatches read every declared active-rule state name and color; the drawer scrolls
when a catalog defines more states than fit at once. Right-click remains erase
and Wireworld shortcuts remain synchronized. Drawing and hit testing share a fitted UI scale;
palette gestures capture pointer input until release. The drawer anchors above the controls-hint band,
fits the remaining height, and leaves footer input to the hints. The opaque
footer covers the bubble's lower half and any morph overflow. Modal menus and the console
take precedence. Entering Edit staggers the hint bar before the palette bubble,
and both pop up on springs that bounce past their slots while the canvas inset
stays clamped;
leaving Edit staggers the bubble before the bar, and both ease away without
ringing. The canvas reservation follows the visible footer area. The bubble
travels by its visible height plus the footer
height before it is removed. Reduced UI motion snaps the transition. The module owns these ordinary
GameVisuals on the existing UI layer.
Camera navigation accepts finite world coordinates with absolute value at most
$16(2^{63}-2^{32})$ per axis, reserving space for bounded cache arithmetic.
Commands, sparse metadata, and pending pan/zoom targets validate this range
before mutation. Saves reject invalid camera metadata before replacement.
Invalid cursor samples are ignored; an invalid direct camera preserves the
previous safe view cache. This presentation margin does not limit sparse cell
storage or guarantee cell-level rendering precision at extreme coordinates.
Clipboard operations iterate bounded local offsets even at signed endpoints.
Elementary rules use background beyond representable X coordinates and omit
unrepresentable children; a source row at maximum signed Y rejects advancement
before changing cells or revision.

class-per-state hierarchy (archived under \pathref{archive/old-states/}).

publish only at frame boundaries; overdue whole steps are dropped while the

are separate, and every rule references one required family. Family data owns
state count, labels, and colors; rule data owns transition parameters. The

New simulation and the menu console command \texttt{play} open a dedicated canvas
setup screen, independent of F1 configuration. It offers the rules catalog,
infinite or wrapping boundaries, width and height in 16-cell increments, and
empty or starter contents. Infinite mode disables dimensions while retaining
the finite draft. Create passes validated canvas values to CellGameModule;
Back or Escape discards the draft. Display and performance preferences are not
part of this payload. The screen fits all rows, respects reduced menu motion,
and consumes wheel input without changing selection or values. Glass cards,
spring-driven focus lighting, the liquid selection drop, springy directional
value nudges, a crossfading boundary badge, and a live glider on a 6x6 torus match
the main menu; reduced motion freezes the motif and snaps focus feedback.

Entering a new or loaded cell canvas plays a 0.9-second cellular wave. A
module-owned, screen-space GameVisual veil tiles the viewport with cells of
roughly 44 virtual pixels, opaque and dark at first. A wave spreads from the
center with a deterministic, per-cell ragged front: each cell fires cyan as the
wave reaches it (with a soft halo), cools to violet, then shrinks to a dot and
fades, revealing the world. Its cell count follows the viewport and UI scale,
and it retires after completion. It covers the canvas and HUD but remains beneath
settings and confirmation dialogs. The transition never changes camera or
simulation state and does not block input. Reduced menu motion and the 3D
diagnostic view skip it from the first frame. Returning to the main menu runs
the wave backwards over 0.48 seconds (cells regrow from the edges inward, fire,
and darken until the canvas is covered), then submits one module transition. Repeated return
requests do not restart it; product input is consumed during the accepted exit,
while the global console retains its input. Reduced motion returns immediately.
Both the pause-menu action and the console menu command use this path.

\subsection{SparseCellGrid (domain) and CanvasView (view --- D-C3)}
\begin{itemize}
  \item Domain: signed 64-bit cell addresses map through floor division into
        non-background 16$\times$16 byte chunks. Negative coordinates and all
        multi-state values are preserved. Infinite mode has no fixed chunk pool
        cap. Finite mode canonicalizes into a centered chunk rectangle and
        wraps both axes.
  \item Simulation: each chunk carries a compact stored-cell occupancy mask and
        a separate neighbor-counting mask plus cached counts for both masks.
        The authoritative and inactive maps maintain aggregate stored-cell,
        counted-cell, and candidate-preferred-chunk totals transactionally
        across edits, local patches, and complete swaps. Settled stepping and
        complete-path selection therefore do not scan every allocated chunk.
        If any source
        chunk has fewer than 48 counted cells, the grid creates exact affected
        targets through a retained generation-stamped
        open-addressed index. Its slots address contiguous scratch records
        containing a 256-bit candidate mask and 256 neighbor counts. It
        derives target participation directly from counting-mask edge and
        corner bits, and initializes a neighbor counter only when its candidate
        bit is first enrolled. Serial preparation remains source-centric for
        locality. For large or explicitly parallel preparation, discovery
        records each target's direct 3-by-3 source references beside its
        neighbor counts. Workers claim retained coarse target ranges and count
        without repeated source-map lookups. Direct dual-grid generations retain
        an object-local topology epoch. When the same source grid returns with
        unchanged chunk presence and counted edge/corner participation, the
        target index and source references are reused exactly. Index-aligned
        destination pointers also avoid output-map lookup when the destination
        topology is unchanged; in-place output preserves their addresses.
        Candidate-index lookup probes existing
        targets before checking whether a new insertion must grow the retained
        table. It evaluates
        only non-background cells and neighbors of counted cells.
        Each target selects candidate or direct halo evaluation independently
        from its counted-neighbor contribution work; counting-dense centers skip
        neighbor-count scratch preparation, and all-dense counted worlds
        bypass scratch construction. This keeps Wireworld conductors separate
        from the heads that actually contribute neighbor counts. Before either
        complete path, a retained changed-chunk frontier records exact state
        and counting-change masks. Every changed chunk enrolls itself, while
        only counting changes on an edge or corner enroll the touching
        neighbor. An empty frontier performs no cell
        evaluation. Up to 16,384 changed addresses are retained for tracking;
        evaluation still follows the frontier/complete work comparison. Sparse local
        sources build candidate masks only for frontier targets and select
        candidates or halos independently. Dense-majority frontiers and
        frontiers with at least 2,048 targets skip candidate scratch and
        evaluate as halo. Exact frontier preparation and
        evaluation work is compared with a complete-path estimate derived from
        cached population totals; cheaper frontiers patch the retained
        prior-generation map directly. At 16,384 or more candidates, retained
        preparation ranges of at most 256 targets and evaluation ranges of
        roughly 2,048 candidate cells use up to four automatic workers and
        independent result slots; smaller sets keep direct serial
        output. Denser worlds use deterministic direct
        halo/core work. Complete targets, their generation-stamped flat index,
        and result slots retain high-water storage. Counted rows are extracted
        directly from chunk masks without materializing an 18$\times$18 byte
        halo; at 32 or more targets a reusable pool evaluates independent cores
        with up to eight workers. Repeated halo neighborhoods may use a bounded
        exact 18$\times$18 state memo. Main and worker shards are lock-free;
        full key comparison proves hits, adaptive sampling enables profitable
        workloads, and ruleset transition changes invalidate entries. Both
        paths write into a retained inactive map
        using recycled node handles before transactional comparison/swap.
        Aggregate inactive statistics reset once before recycling. Sparse
        candidate results construct directly in acquired node storage, while
        dense halo results retain their complete-array bulk copy. Empty
        space is implicit. Infinite mode is non-toroidal. Finite mode enrolls
        canonical wrapped neighbors through the same transition table, so
        horizontal, vertical, and corner seams are exact for binary and
        multi-state rules. The revision changes only when cell contents differ.
  \item Publication: a persistent \symbolref{SimulationRunner} exclusively
        mutates the spare grid while the main thread reads the published grid.
        A completion publishes at a frame boundary. Incremental completions
        carry changed chunk snapshots and update the former display grid before
        it becomes the next worker buffer. Broad completions and journals of at
        least 2,048 presentation chunks carry only a
        replacement marker; the spare advances directly from the immutable
        published grid and updates its own nodes in place. Incremental catch-up uses the grid's retained
        changed addresses and skips states superseded by the incoming delta;
        Only one request may be outstanding. Status separates rolling mirror,
        advance, and capture latency.
  \item View: \symbolref{CanvasView} samples a globally aligned camera cache
        padded by two chunks per side. Motion inside it changes only the MVP;
        aligned origin shifts copy retained texels and resample newly exposed
        strips. Far-zoom strips initialize background bins and accumulate only
        occupied cells from intersecting sparse chunks instead of probing every
        covered source cell. Published generations map exact changed-cell masks
        to deduplicated cache bins. Far-zoom bins reset together, accumulate in
        one occupied-chunk traversal, and finalize once; dense exact-cell
        changes may still select a complete cache sample at the quarter-cache
        threshold. Overview resamples walk occupied cells and snap-convert
        sampled RGB in one pass.
        Near zoom is one texel per cell; far zoom uses integer density LOD with
        80\% refinement hysteresis. Revision gaps, non-aligned jumps, LOD/resize,
        palette changes, torus wrap, and replacement perform a bounded refill.
        Exact-cell LOD fades changing colors; density overviews snap. Finite worlds are
        drawn only inside their centered canonical rectangle; camera space
        outside it stays background-colored while opposite-edge simulation
        neighbors still wrap. A theme-accented outline keeps all four wrap
        edges visible at a stable screen thickness without tiling the world.
        Their changes conservatively trigger a bounded refill.
  \item GPU: one reusable nearest-filtered RGB display texture and one
        world-space \symbolref{GameVisual} quad that shares its cell bounds
        with the editor cursor. Dirty 16$\times$16-texel tiles merge into at
        most eight rectangles or their enclosing AABB.
  \item Dense \symbolref{CellGrid}/\symbolref{Canvas} remains only for
        compatibility tests and legacy import, not as a second runtime path.
\end{itemize}

\subsection{Scale walls (simulation / memory)}
\begin{statusbox}
Sparse simulation cost follows stored cells, counted cells, and their local
birth candidates, not a fixed world rectangle. Mixed targets independently use
candidates or chunk halos; 32 or more halo targets use up to eight reusable CPU
workers. A cached 256-state by 9-neighbor transition table serves every hot
loop, dense halos use rolling three-row neighbor counts, and profitable
repeated 18$\times$18 states use an exact bounded memo. Presentation uses
a padded camera cache, changed-chunk bins at every LOD, overview snaps, and an
active-texel fade set at exact-cell zoom; fallback refills remain bounded and
far-zoom output stays near one texel
per four screen pixels. GPU
resources do not scale with chunk count.
\end{statusbox}

\subsection{Rulesets}
The shipped \pathref{families.json} defines cell-state schemas and palettes;
\pathref{rulesets.json} defines Game of Life, Brian's Brain, Day
\& Night, Highlife, Life Without Death, Seeds, Wireworld, Rule 90, Rule 184,
Star Wars, Nova Trails, two Excitable Waves thresholds, Prism Rush, Chromatic
Storm, Crystal Domains, Elemental Surge, and Aurora Conflict.
The researched expansion adds Immigration, QuadLife, Bosco/Bugs, Bugsmovie,
Globe, Banners, Transers, Fireworks, and the classic 14-color cyclic automaton.
\texttt{RuleSetRegistry} starts empty, validates text transactionally, and
compiles version-3 rule definitions referencing version-1 family definitions.
Families own their stable IDs, simulation models, state counts, labels, and
colors. Rules own stable IDs, names, one required family ID, and transition
parameters. Unversioned and schema-v1/v2 legacy rule catalogs remain readable
and normalize into separated definitions. Life-like, Generations, and
colorized-Life rules
compile from B/S neighbor counts; Wireworld and the five-phase excitable-media
family are Moore tables. The twelve-state Prismatic Ecology and nine-state
Elemental Court are cyclic families: a cell advances by a coprime step when its
successor state meets the rule threshold among eight neighbors. The four-phase Generations family shares a neon decay
schema between Star Wars (B2/S345/C4) and Nova Trails (B23/S34/C4). The
excitable-media family shares an excited/resting/three-stage refractory schema;
its two rules activate resting cells at thresholds one and two. Rule 90 / 184 use the dedicated
\texttt{NeighborhoodKind::}\allowbreak\texttt{Elementary1D} serial history
path (D-G2). Adding a definition requires no C++ factory change while it fits
one of these families.

Immigration and QuadLife count every non-background state as live. Survival
retains the current species; births inherit the majority parent color, except
that three distinct QuadLife parents produce the absent fourth species. They
reuse the full-state Moore histogram path. The classic cyclic rule implements
the 14-color random-initial-condition experiment described by Fisch, Gravner,
and Griffeath.

Larger-than-Life definitions carry range, optional center counting, inclusive
birth/survival intervals, and square, circular, or diamond neighborhood shape.
Range is bounded to 16 and B0 is rejected. Bosco/Bugs, Bugsmovie, and Globe use
the parameters documented by Golly. Their serial sparse kernel expands occupied
chunks by the required chunk radius and reads each target's canonical halo
window before transactional output publication; it does not alter the
optimized radius-one paths.

Rules may also own deterministic starter data. Active soups drive Generations
and Larger-than-Life, phase soups drive cyclic systems, species soups include
every live kind, and excitable breaks replace the former generic glider for
wave media. Research sources are Golly's official Generations and
Larger-than-Life documentation, Fisch--Gravner--Griffeath's 1991 paper, and the
January 1979 BYTE Quad-Life description.

The second researched expansion adds Hodgepodge chemistry, Turmites, HPP
lattice gas, and five-species dominance. Hodgepodge exposes 101 color levels
and computes healthy infection, active averaging, and ill recovery from the
complete Moore histogram. RPSLS uses the same histogram with two prey offsets
per species and deterministic synchronous invasion thresholds.

Turmites and HPP preserve north/east/south/west identity through
\texttt{NeighborhoodKind::}\allowbreak\texttt{VonNeumannDirectional}.
The RL, RRL, and RRLL Turmites combine two to four tape colors with four agent
directions per color. HPP's sixteen states encode every combination of four
directional particles; opposing pairs rotate before streaming. Both dense
compatibility and serial sparse execution use the same direction ordering and
transactional publication. Deterministic agent swarms and particle clouds make
these rules move immediately. Sources include Dewdney's contemporary account
of the Gerhardt--Schuster Hodgepodge Machine, Moreira and Gajardo's Turmite
formalization, Hardy--Pomeau--de Pazzis lattice gas, Toffoli and Margolus's
cellular-automata treatment, and Vukov--Szolnoki--Szabó five-species dominance.

The third expansion (D-GC8) adds self-replication, sandpiles, long-range
cycles, and trails. \texttt{von\_neumann\_table} families store Golly
\texttt{@TABLE} text verbatim and compile it to a dense lookup of $n^5$
entries for at most twelve states. The compiler follows Golly: the first
matching transition wins, a variable repeated in one transition binds to one
value, symmetries expand every written transition, and unmatched
neighborhoods keep their center. Golly's quiescent state 0 swaps with Illumo's
background state 1. Langton's, Byl's, Chou--Reggia, SDSR, and Evoloop tables
ship with their published starting loops as exact RLE starters, and their
evolution is checked against an independent reference implementation.

\texttt{sandpile} families hold heights 0--7 in the background-zero encoding
and then the phases of a pulsed grain source. A cell with four or more grains
topples one grain to each von Neumann neighbor; the dropping source phase
emits four grains without depleting. Mandala, binary-star, and
critical-square starters grow the Abelian sandpile fractal.

Cyclic rules accept an optional range and square, circular, or diamond shape.
Radius-one square rules keep the Moore histogram path; wider rules implement
Griffeath's cyclic automata (313, Lava Lamp, Stripes, Squarish Spirals, Cyclic
Spirals, Turbulent Phase) on the extended-range kernel, which counts the state
returned by \texttt{getExtendedCountedState}: the successor for cyclic rules
and the active state otherwise. Because a full cycle also advances the empty
background, such soups would invade the infinite canvas at up to their radius
per generation; the Griffeath rules therefore set \texttt{inert\_background},
which removes state 1 from the cycle so each soup stays in its dish. Larger than Life gains the diamond shape and
Golly's C-state decay trail, in which a dying cell walks states $2..C-1$
without counting or accepting births; Comet Rockets' light-speed spaceships and
the Rainbow Tides, Neon Coral, and Bubble Swarm soups use it. The extended and
directional kernels read each target chunk and its margin into a halo window
once rather than hashing every neighbor lookup. Forty-five further classic
Life-like and Generations rules from Golly and MCell complete the catalog.

Game's \texttt{RuleCatalogLoader} selects the first valid base family/rule
catalog pair beside the executable, in the working directory, or in its
\texttt{IllumoGame} subdirectory. It then transactionally layers the
working-directory \pathref{families.user.json} and
\pathref{rulesets.user.json}; later matching IDs replace earlier definitions.
Invalid or unreadable base files fall through, and malformed overlays preserve
the active catalog. The module factory loads the catalog once before
menu/direct-game construction. The engine's configuration path supplies
executable location; Rulesets has no filesystem or native API dependency.
Callers use the loader for files and \texttt{loadFromText} for text (D-GC1,
D-GC2, D-GC4).

In the package, the control guest's \texttt{CSimCatalogBootstrap} replaces
the native file lookup with a staged sequence over the guest SDK's
\texttt{GuestFiles}, pumped once per update: read the packaged
\pathref{families.json}/\pathref{rulesets.json} pair from \texttt{/app}, list
\texttt{/packages}, list each \texttt{/packages/<id>/csim} directory for
\texttt{*.json} (packages in id order, files in name order, at most 64), read
those catalogs, then apply. Package catalogs merge after the packaged pair and
before the storage \pathref{families.user.json}/\pathref{rulesets.user.json}
overlays, so a player's own edits still win. Files named
\texttt{families*.json} add families and every other name adds rules. Each
catalog merges into a candidate copy of the registry; an invalid one is skipped
with a logged warning, and the game logs what merged. Both paths stage
overlays through the portable \texttt{RuleCatalogOverlay}. A content package
that ships \pathref{csim/*.json} therefore extends the rule catalog without
replacing the base files (D-E21).

F1, New Simulation, runtime status, and saved worlds carry an
explicit family/ruleset pair. Save version 4 writes both IDs; version 3,
version 2, and dense legacy readers derive the family from the saved rule ID.

\textbf{Generation:} Full-state, directional von Neumann, and extended-range
rules first route to their isolated correctness kernels. Radius-one count rules
use the optimized path below.
\begin{enumerate}
  \item Read cached stored/counting totals and the candidate-preferred chunk
        count. If the retained changed frontier is empty, return immediately
        without visiting allocated chunks. Otherwise build its one-chunk
        affected set from exact counting-change edge/corner bits and, for sparse
        local sources, target-local candidate masks.
  \item Compare exact frontier target/source bookkeeping, candidate,
        neighbor-contribution, and evaluation work with a complete-path
        estimate derived from cached totals. Patch the retained map when the
        frontier is no more expensive; otherwise use a complete path. Retain
        at most 16,384 changed addresses for tracking; the work comparison still
        selects evaluation. Edits and ruleset-type changes
        repopulate the frontier.
  \item Use the cached candidate-preferred count to select the complete
        adaptive or all-dense path.
  \item If any source chunk is counting-sparse, create exact affected targets
        directly through the
        retained generation-stamped flat index, reset their contiguous
        masks/counts, mark non-background cells plus neighbors of counted cells,
        then choose candidate bits or a direct halo independently for each
        target from counted-neighbor contribution work. Counting-dense centers
        skip neighbor-count scratch preparation. Dense-majority frontiers and
        frontiers with at least 2,048 targets skip candidate scratch. Large
        sets are divided
        into coarse work-count ranges for the reusable worker pool.
  \item If all source chunks are counting-dense, bypass candidate scratch.
        Build the expanded target set in a retained generation-stamped flat
        index and reuse retained target/result storage. Extract 18-bit counted
        rows directly from the nine chunks' masks, reduce them through three
        rolling horizontal rows, and evaluate serially or through the bounded
        worker pool for 32 or more targets.
  \item For at least 32 halo targets, sample the exact sharded neighborhood
        memo. Activate it only when its observed hit rate offsets key creation;
        cool it down for unique inputs and invalidate it by exact comparison
        of the complete transition table. Instance revisions and rule names
        cannot identify transition semantics across different ruleset objects.
  \item Install non-background results serially into the retained inactive map,
        reusing extracted chunk-node handles before allocating new nodes. Build
        sparse candidates directly in mapped node storage and bulk-copy dense
        halos. Compare
        and swap transactionally only when contents differ.
\end{enumerate}

Before worker dispatch, the active ruleset lazily builds its 2,304-entry
transition table. Candidate, halo, and compatibility dense loops index this
immutable table rather than invoking virtual transitions for every cell.
Cyclic rules instead use an isolated serial sparse kernel that expands occupied
chunks by one, counts all byte-valued neighbor states, and reuses the existing
transactional output and change journal. The optimized count-table paths remain
unchanged. Dense compatibility evaluation uses the same histogram contract.
Colorized-Life shares that histogram kernel. Larger-than-Life uses a separate
serial extended-range kernel and the same transactional result/change-journal
machinery. Hodgepodge and dominance share the histogram kernel; Turmites,
HPP, rule tables, and sandpiles share the serial direction-preserving kernel.

\begin{decisionbox}[title={Keep rules pure}]
Rulesets stay free of rendering and input. They read/write cell buffers only
and expose \texttt{evalCell} for palette colors. That keeps them testable
(headless \texttt{TestRuleSets}).
\end{decisionbox}
